# Версии Zikr Adventure и GitHub

- Основной репозиторий: https://github.com/khisomovkomron/zikr-adventure.
- GitHub хранит исходники и историю всех версий. Для каждого следующего выпуска создавать отдельную ветку `codex/release-X.Y.Z` от актуального main; для небольших задач можно использовать отдельные ветки и PR в ветку выпуска.
- После проверок создавать или обновлять pull request в main. Не сливать непроверенный выпуск автоматически; слияние — после завершения QA и согласования пользователя.
- Новые папки версий для будущих выпусков больше не обязательны: пользователь заменил этот процесс ветками Git. Существующие папки 1.0.0 и 1.0.1 сохранить как часть первоначального переноса.
- `ZikrAdventure-AppStore/` — неизменяемая исходная опубликованная 1.0.0. `ZikrAdventure-1.0.1/` — рабочая версия 1.0.1 в ветке выпуска.
- Для последующих изменений использовать рабочий проект, избегая новых дубликатов папок. Теги выпусков создавать для проверенных исходников; факт публикации подтверждается отдельно App Store Connect.
- Обновлять MARKETING_VERSION в project.yml и project.pbxproj согласованно. Build выбирать выше последнего загруженного в App Store Connect.
- Сохранять bundle identifier и ключи хранения прогресса для совместимости обновлений.
- Не загружать токены, credentials, .env, подписи, локальные данные Xcode и временные артефакты.
- Перед выпуском проверять сохранение, восстановление, нажатия, отмену, сброс и смену дня. JS-тесты и компиляция не подтверждают поведение iOS.

# Учёт работы в Jira

- Проект: https://zikr-app.atlassian.net/browse/ZKR (ключ ZKR).
- Для работы с Jira и Confluence в первую очередь использовать подключённый Atlassian connector, избегая браузерной автоматизации. REST API через tools/jira_api.py — резервный вариант при недоступности connector.
- Перед созданием задачи проверять существующие задачи, чтобы не создавать дубликаты.
- Каждую новую работу записывать в Jira с описанием, критериями готовности и целевой версией; по ходу работы обновлять результат и статус.
- Исправленный код с незавершённой проверкой WKWebView оставлять In Review. Не объявлять проверку на устройстве завершённой по результату JS-теста или компиляции.
- Не изменять чужие задачи, права доступа или настройки проекта без соответствующего запроса.
- Токен читать только из локального файла credentials или переменных окружения. Не добавлять токен в код, Git, Jira, вывод команд или сообщения. Локальный credentials-файл временный; при его отсутствии запросить повторную настройку.

# Документация и управление релизами

- Внутренние задачи Jira, документация Confluence, решения и описания релизов ведутся на русском языке. Материалы для App Store готовятся на английском.
- Для каждого изменения обновлять задачу Jira и соответствующую документацию Confluence: проблему, принятое решение, итоговое поведение, проверки и ограничения. Связывать страницы и задачи ссылками.
- Для каждого выпуска вести запись релиза: версия, статус, состав задач, изменения, совместимость/миграции данных, результаты QA, известные проблемы, build, план публикации и восстановления.
- Статусы релиза: Планируется → В разработке → На проверке → Готов к публикации → Опубликован. Статус Опубликован и фактическую дату устанавливать только после подтверждения App Store.
- В Jira использовать fixVersions для принадлежности задач к выпуску; labels не заменяют версию релиза. Не помечать version released до подтверждённой публикации.
- При недоступности Confluence сохранить готовую документацию в docs/ и явно указать, что синхронизация не выполнена. Не считать локальный файл опубликованной страницей.
- Перед обновлением существующей страницы читать её актуальную версию и сохранять чужие правки. Не менять доступ и не включать публичные ссылки без запроса.

- Confluence: пространство Software Development (SD), ID 196612; корень документации Zikr Adventure — страница 229378. Точные ID страниц находятся в docs/confluence.json. Обновлять существующие страницы, не создавать дубликаты. Страницы созданы приватными для владельца; расширять доступ только по запросу.
