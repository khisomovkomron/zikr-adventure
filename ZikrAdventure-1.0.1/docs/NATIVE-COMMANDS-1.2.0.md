# ZKR-59: нативные команды и миграция

Jira: https://zikr-app.atlassian.net/browse/ZKR-59
Confluence: https://zikr-app.atlassian.net/wiki/spaces/SD/pages/9666564
Версия 1.2.0, ветка `codex/zkr-59-native-commands`, [Draft PR #17](https://github.com/khisomovkomron/zikr-adventure/pull/17) в `release/1.2.0`.

## Что сделано

`NativeProgressReducer` в Domain переносит действия счётчика, отмену, оба сброса, настройки/язык/defaults, историю, полный сброс, просмотр/переходы глав, город, камеру и завершение онбординга. Связи глав с городами передаются каталогом из composition root, тексты/контент в Domain не копируются. Навигация, volatile session, геометрия камеры и feedback остаются ответственностью UI.

`JSONStateStore.execute` читает, применяет и записывает команду в одной actor-операции без await внутри транзакции. Ответ возвращается после успешной атомарной записи. Ошибка записи сохраняет прежний cache. Без завершённого bootstrap команды отклоняются; недоступный либо будущий файл не превращается в свежий прогресс.

Сохранены прежние правила: undo затрагивает сегодняшний daily и не закрывает главы; reset(counter/all) оставляет историю, настройки, onboarded, камеры и выбранный город, all дополнительно очищает unlocked/viewed. resetProgress очищает прогресс и карты, сохраняет настройки, ставит onboarded=true, как веб. Повторные completeOnboarding/markViewed не переписывают файл.

Числовые правила: total/daily ограничены Number.MAX_SAFE_INTEGER как в сохранённом legacy-снимке. Неверные числа/камеры и неизвестные города/главы отклоняются. updatedAt растёт даже при переводе часов назад и полном resetProgress. При исчерпании безопасного диапазона операция отклоняется вместо переполнения.

## Что остаётся

На этапе A команды не использовались в AppContainer. Текущее подключение выполнено на этапе B, описанном ниже. Следующий этап — проверяемая миграция legacy-источников и переключение всех sink на native writer; затем ZKR-58/устройство и удаление WebView/ресурсов. Нельзя объявлять ZKR-59 выполненной по этому PR. Физический iPhone, iOS UI, обновление поверх App Store, размер/время запуска и App Privacy этим прогоном не проверялись. Версия/build и подписи не менялись.

Для прямого обновления с HTML требуется отдельно проверить чтение старого localStorage: WKWebsiteDataStore сам не предоставляет API значений ключей. Пользовательские источники не удаляются; ошибка чтения должна блокировать fresh-инициализацию. Решение описывается до переключения.


## Этап B: миграция и live-подключение

В этой же ветке/PR добавлены NativeRootView и NativeCommandSink. Все live-команды идут в JSONStateStore; старый WebHost не создаётся, зеркало не подключается, legacy save отклоняется. Веб-ресурсы и старые классы остаются в исходниках до ZKR-58 и финального удаления (этап D).

Bootstrap блокирует UI до готовности. Сначала проверяется optional meta.nativeWriterActivated в прежней schema 3. Для ещё не активированного профиля проверяется доступность защищённых данных, затем headless LegacyStorageReader читает v2/v1 с прежнего origin zikr://localhost через default WKWebsiteDataStore, без index.html и message handlers. progress.json читается отдельно с различением отсутствия и I/O-ошибки. Ошибка даёт локализованный экран повтора, не fresh-прогресс.

activateNative сверяет legacy-снимок с shadow по updatedAt (новый reset с меньшим total побеждает старый больший счёт), при отсутствии timestamp сохраняет прежнее merge-правило. Данные и флаг активации записываются атомарно; после него legacy не импортируется и replaceFromWeb заблокирован. Старые ключи/файлы не очищаются. Схема, bundle ID, версия и build не меняются.

NativeRootView показывает только SwiftUI-экраны и прежний tab bar; auth активируется без WebHost. idle timer управляется нативными настройками/состоянием сцены. Модель онбординга получает восстановленный флаг до показа UI; завершённый профиль не проходит промежуточную загрузку модального онбординга. UI-тесты используют отдельный UITests/zikr-state.json; fixtures не меняют обычный профиль.

WebKit остаётся временно для совместимости прямого обновления со старой HTML-версии. Это не WebKit UI и не выполнение бизнес-логики JS. Буквальное отсутствие WKWebView в проекте пока не заявляется. JavaScriptCore-отрисовка спрайтов карты также сохранена по прежней архитектуре.

Проверки этапа B: пакет — 124 XCTest PASS (56 Persistence / 28 Domain / 4 Core / 36 Content). Первый целевой iOS-прогон — 8/8 PASS, включая реальный same-origin reader, native sink, ошибку bootstrap и повтор. Повторный прогон: 6 моделей онбординга и 2 native-bootstrap теста PASS; same-origin тест завершился ошибкой WebContent/InvalidTransition после неотзывчивого процесса. Первый UI-сценарий skip/completed/123 PASS в отдельном прогоне; следующий был прерван. Финальные результаты и ограничения уточняются после целевой проверки на перезапущенном симуляторе. Эти промежуточные результаты не означают полный зелёный iOS QA.


Дополнительная защита: постоянный путь Application Support вычисляется без создания каталога и без fallback во временную папку. Нативный файл читается только после isProtectedDataAvailable; ошибки чтения, включая запрет доступа к родительскому каталогу, отличаются от отсутствия файла. Тест восстанавливает тот же файл со счётом 99 после возврата разрешений, без перезаписи байтов. Legacy-reader создаётся лениво только если отсутствует флаг завершённой миграции; повторный запуск вообще не создаёт WebKit data store.
