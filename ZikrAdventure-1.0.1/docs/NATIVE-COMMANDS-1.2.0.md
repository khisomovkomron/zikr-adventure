# ZKR-59/A: нативные команды

Jira: https://zikr-app.atlassian.net/browse/ZKR-59
Confluence: https://zikr-app.atlassian.net/wiki/spaces/SD/pages/9666564
Версия 1.2.0, ветка `codex/zkr-59-native-commands`, PR в `release/1.2.0`.

## Что сделано

`NativeProgressReducer` в Domain переносит действия счётчика, отмену, оба сброса, настройки/язык/defaults, историю, полный сброс, просмотр/переходы глав, город, камеру и завершение онбординга. Связи глав с городами передаются каталогом из composition root, тексты/контент в Domain не копируются. Навигация, volatile session, геометрия камеры и feedback остаются ответственностью UI.

`JSONStateStore.execute` читает, применяет и записывает команду в одной actor-операции без await внутри транзакции. Ответ возвращается после успешной атомарной записи. Ошибка записи сохраняет прежний cache. Без завершённого bootstrap команды отклоняются; недоступный либо будущий файл не превращается в свежий прогресс.

Сохранены прежние правила: undo затрагивает сегодняшний daily и не закрывает главы; reset(counter/all) оставляет историю, настройки, onboarded, камеры и выбранный город, all дополнительно очищает unlocked/viewed. resetProgress очищает прогресс и карты, сохраняет настройки, ставит onboarded=true, как веб. Повторные completeOnboarding/markViewed не переписывают файл.

Числовые правила: total/daily ограничены Number.MAX_SAFE_INTEGER как в сохранённом legacy-снимке. Неверные числа/камеры и неизвестные города/главы отклоняются. updatedAt растёт даже при переводе часов назад и полном resetProgress. При исчерпании безопасного диапазона операция отклоняется вместо переполнения.

Новые тесты: 200 конкурентных нажатий без потерь и восстановление после перезапуска, пороги/undo, смена дня/часового пояса, оба сброса, все переключатели/языки, история, карта/главы, повторные действия, числовые границы, недоступный/будущий файл, неудачная запись.

`node tools/native-command-fixtures.cjs --check` — PASS. Генератор выполняет настоящие функции из index.html; Swift сравнивает 27 последовательных шагов из четырёх golden-сценариев. DOM/рендеринг и системные эффекты подменены; данные меняет исходный JS. Timestamp сравнивается отдельными инвариантами: native объединяет промежуточные web persist в одну запись и сохраняет монотонность при resetProgress. Остальные поля прогресса и fresh сравниваются полностью. Эталон не утверждает идентичность UI или поведения WebKit.

## Что остаётся

Эти команды ещё не используются в AppContainer: нет параллельных писателей и изменений поведения опубликованной версии. Следующий этап — проверяемая миграция legacy-источников и переключение всех sink на native writer; затем ZKR-58/устройство и удаление WebView/ресурсов. Нельзя объявлять ZKR-59 выполненной по этому PR. Физический iPhone, iOS UI, обновление поверх App Store, размер/время запуска и App Privacy этим прогоном не проверялись. Версия/build и подписи не менялись.

Для прямого обновления с HTML требуется отдельно проверить чтение старого localStorage: WKWebsiteDataStore сам не предоставляет API значений ключей. Пользовательские источники не удаляются; ошибка чтения должна блокировать fresh-инициализацию. Решение описывается до переключения.
