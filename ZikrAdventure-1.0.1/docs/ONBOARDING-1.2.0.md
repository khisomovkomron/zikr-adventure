# ZKR-65 — нативный первый запуск

План и результаты: https://zikr-app.atlassian.net/wiki/spaces/SD/pages/9338882
Задача: https://zikr-app.atlassian.net/browse/ZKR-65

Решение Комрона от 18.11.2026: включить нативный онбординг в 1.2.0, сохранить поведение веб-версии. Три шага, выбор шести языков на первом шаге, пропуск с любого шага, завершение на третьем. Возврата между шагами и обязательной регистрации нет, как в исходнике.

`OnboardingViewModel` создаётся в AppContainer и показывает загрузку до получения `onboardingStatus()` от уже восстановившего данные веба. DOM `#onb` не используется как источник состояния нативного пути. Онбординг открывается через fullScreenCover с запретом интерактивного закрытия. Его дерево доступности содержит отдельные кнопки; веб-подложка скрывается на уровне UIKit, нижние вкладки — отдельно. Пока онбординг открыт, вкладки под ним недоступны для касаний и VoiceOver. После завершения опрос прекращается.

`OnboardingCommandSink` отделяет UI от записи. Пока единственный писатель — веб: `completeOnboarding()` идемпотентно устанавливает прежний `state.onboarded`, сохраняет через `persist()` и закрывает веб-слой. Native скрывается только после успешного ответа. При ошибке можно повторить. Revision-счётчик не позволяет запоздалому запросу статуса отменить завершение или вернуть прежний язык. Смена языка проходит через SettingsCommandSink; прогресс и схема хранения не меняются. Сброс прогресса сохраняет завершение онбординга.

`AppContainer.isNativeOnboardingEnabled=false` возвращает веб-путь. Тексты onb.* генерируются из существующего UI-словаря; ключи хранения, bundle ID, версия и build не изменены. WebView остаётся до ZKR-59.

## Проверки

- `tests/onboarding-native.cjs`: идемпотентность, сохранение остальных полей, отсутствие двойного UI.
- `OnboardingViewModelTests`: восстановление, три шага, пропуск/ошибка/повтор, шесть языков, конкурентное завершение.
- `OnboardingScreenUITests`: завершение, язык, сохранение 123 повторений после перезапуска, пропуск, пользователь с завершённым онбордингом, снимки языков/тем и веб-оригинала.
- Старые UI-тесты умеют пропускать как нативный, так и веб-онбординг.

В DEBUG доступны фикстуры при ZIKR_UITEST_AUTH=guest: ZIKR_UITEST_ONBOARDING=fresh|completed и ZIKR_UITEST_WEB_ONBOARDING=1 для сравнения. Они заменяют данные тестового приложения; запускать только на выделенном симуляторе. В Release фикстуры отсутствуют.

Проверка на физическом iPhone и обновление поверх установленной App Store-версии требуют отдельного подтверждения; симулятор их не заменяет. Результаты прогонов записываются после завершения в Confluence и PR.

## Результаты 18.11.2026

- Компиляция Debug для iOS Simulator — успешно.
- 5 OnboardingViewModelTests — успешно.
- Все 3 OnboardingScreenUITests — успешно в целевых прогонах: пропуск/существующий пользователь, три шага/язык/перезапуск, матрица языков/тем.
- В UI проверены выбор русского языка и три шага; после перезапуска сохранён счёт 123, завершённый онбординг не появляется повторно.
- 9 Node-наборов и три проверки генераторов — успешно.
- 18 итоговых снимков сохранены в `qa/zkr-65/`: шесть языков первого шага в двух темах, второй/третий шаг и веб-оригинал. Светлая и тёмная темы проверены просмотром снимков, а не только именами файлов.
- Исправлена модальность/доступность: fullScreenCover, отдельное скрытие веб-подложки и отдельных вкладок. Тест проверяет недоступность касаний по вкладке под модальным экраном; глобальная exists в XCTest не является проверкой VoiceOver.
