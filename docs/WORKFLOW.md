# Организация работы над Zikr Adventure

Внутренняя документация и задачи ведутся на русском. App Store: описание приложения, What’s New и материалы публикации — на английском.

## Источники информации

- Jira, проект ZKR: задачи, приоритеты, ответственные, критерии готовности, статусы и принадлежность к релизу.
- Confluence: требования, решения, описание поведения, архитектура, инструкции и документация выпусков.
- Репозиторий: исходный код, история изменений и локальная копия документации.
- App Store Connect: фактические номера загруженных сборок, проверка Apple и состояние публикации.

Исходники и история всех версий хранятся в [GitHub](https://github.com/khisomovkomron/zikr-adventure). Main содержит базовую 1.0.0; рабочая 1.0.1 ведётся в codex/release-1.0.1. Следующие выпуски создаются в новых ветках, проходят проверку и pull request, затем сливаются в main по согласованию. Существующие папки сохранены при первоначальном переносе; для будущих выпусков новые папки больше не обязательны.

## Порядок выполнения задачи

1. Найти или создать задачу Jira. Описать проблему, критерии готовности, целевой релиз и зависимости.
2. При начале работы перевести задачу в In Progress.
3. После изменений записать итоговое поведение, затронутые компоненты, проверки и ограничения. Обновить документацию Confluence и добавить взаимные ссылки.
4. Передать задачу в In Review. Компиляция и тесты с моделями DOM не заменяют проверку на iPhone/WKWebView.
5. Перевести задачу в Done после выполнения её критериев. Отдельно фиксировать публикацию релиза: завершённая задача не означает опубликованную версию.

Если Confluence недоступен, документ готовится в docs/, а непроведённая синхронизация явно отмечается. При публикации используется уже подготовленный текст; данные и ссылки актуализируются. Права доступа без запроса не меняются.

## Управление релизами

Статусы: Планируется → В разработке → На проверке → Готов к публикации → Опубликован.

Для каждого выпуска создаются Jira version и страница Confluence. Задачи связываются через fixVersions. Запись релиза содержит версию, состав изменений, задачи, совместимость и миграции, проверки, известные проблемы, build, план публикации и восстановления.

Перед публикацией:

- Проверить критерии всех включённых задач и обязательные сценарии: сохранение, восстановление, отмена, сброс, смена дня, обновление с предыдущего выпуска.
- Проверить работу на целевой iOS и iPhone; зафиксировать устройство и результаты.
- Сверить номер build с App Store Connect, выбрать следующий свободный и собрать подписанный архив.
- Подготовить английский текст What’s New и необходимые материалы App Store.
- Зафиксировать согласованный состав релиза и готовность к публикации.

После фактического выхода записать дату, версию/build и подтверждение публикации; отметить Jira version как released. Не назначать фактическую дату публикации заранее.

## Восстановление после неудачного выпуска

Сохранённая папка предыдущей версии позволяет восстановить исходники. Она не позволяет автоматически откатить уже установленное приложение пользователей. При проблеме оценить необходимость остановки дальнейшего распространения, затем подготовить исправленный выпуск с новым build/версией. Перед использованием старого кода проверить совместимость сохранённых данных.
