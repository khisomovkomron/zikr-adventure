# 1.1.0 — Google + Apple: спецификация

Статус: требования определены, реализация не начата. Minor release 1.1.0.

## Цель и границы

Добавить необязательный вход через Google и Apple в существующее iOS-приложение. Пользователь без аккаунта продолжает пользоваться счётчиком, картами и главами. Первый успешный вход создаёт аккаунт через провайдера без отдельного пароля.

В релиз не входят Facebook, email/password, социальные функции, облачное сохранение и синхронизация счётчика, объединение аккаунтов разных провайдеров и обязательный вход. Экран аккаунта прямо сообщает: «Счёт и история пока хранятся только на этом устройстве. Вход не включает облачное сохранение».

## Продуктовые правила

- Вход доступен из настроек; запуск приложения не блокируется экраном авторизации.
- Google и Apple предлагаются как равноценные способы входа с официальным оформлением кнопок.
- Вход, отмена, ошибка, выход, истечение сессии, смена провайдера и удаление аккаунта не меняют localStorage, progress.json, общий счёт, историю, главы и настройки.
- Существующий прогресс остаётся устройственным и не привязывается к UID. При смене аккаунта на том же устройстве показывается тот же локальный прогресс; об этом сообщается в интерфейсе. Реализацию будущих личных облачных данных потребует отдельный релиз и миграция.
- Имя и email необязательны для отображения. Для Apple email может быть скрытым, а имя отсутствовать при повторном входе. Основной идентификатор аккаунта — Firebase UID, а не email.
- Одинаковый email у разных провайдеров не используется для автоматического объединения аккаунтов. Ошибка конфликта не приводит к потере текущей сессии или прогресса; доступна понятная подсказка воспользоваться первоначальным способом входа.
- Без интернета счётчик работает. Вход и удаление аккаунта требуют сети; ранее сохранённое состояние входа отображается без обещания актуальной серверной проверки.
- Выход прекращает сессию авторизации, возвращает режим без аккаунта и сохраняет локальный прогресс.
- Удаление аккаунта доступно в приложении, требует отдельного подтверждения и при необходимости повторного входа. Удаляется учётная запись; локальный прогресс сохраняется. Отдельный существующий «Сбросить весь прогресс» остаётся операцией удаления данных устройства.
- Для Apple при удалении отзываются связанные токены согласно документации провайдера. Если отзыв/удаление не подтверждены, UI не сообщает ложный успех и предлагает повторить.

## Архитектура

Firebase Authentication, FirebaseCore и нативные GoogleSignIn/AuthenticationServices. Firestore и Analytics не подключаются. Firebase UID и минимальные профильные данные доступны UI; provider tokens и refresh tokens не передаются в JavaScript, Confluence или логи.

Swift AuthCoordinator обслуживает состояние guest / signingIn / signedIn / error / deleting. Восстановление сессии выполняется через FirebaseAuth listener. Только одна операция входа/удаления одновременно; отмена и запоздавшие callbacks не заменяют более новое состояние.

HTML отправляет allowlisted команды auth.signInGoogle, auth.signInApple, auth.signOut, auth.deleteAccount и auth.getState. Мост принимает команды только из основного доверенного документа zikr://localhost. В HTML не размещаются OAuth-страницы: провайдеры открываются нативно. UI получает только проверенное JSON-состояние, без исполнения пользовательского текста как кода/HTML.

## Контроль доступа и окружения

Для тестов предпочтителен отдельный Firebase-проект от production. Google/Apple providers и bundle identifier com.komronkhisomov.zikradventure настраиваются владельцем. Provider secrets и Apple .p8 хранятся вне Git и клиента. GoogleService-Info.plist — конфигурация клиента, не service-account key; процесс подключения фиксируется отдельно. Реальная авторизация не имитируется при отсутствии конфигурации: тестовые состояния разрешены только в отдельном UI-прототипе.

## Проверка выпуска

- Реальный вход обоими провайдерами, отмена, отказ, плохая сеть и повторное нажатие.
- Восстановление сессии после перезапуска; выход и повторный вход; Apple Hide My Email и отсутствие имени.
- Отдельно: отклонённые/отозванные credentials, ошибки конфликта аккаунтов, повторная авторизация и удаление аккаунта.
- До и после каждой операции сравнить весь локальный прогресс; он должен совпадать.
- Нажатия и сохранение прогресса без сети продолжают работать.
- Все шесть текущих языков, VoiceOver, Dynamic Type/масштабирование, маленький экран и тёмная тема.
- Обновить privacy policy, тексты «нет регистрации/интернета», App Store privacy disclosures по фактическому использованию SDK.
- Сверить номер build в App Store Connect; TestFlight QA не означает публикацию App Store.

## Последовательность задач

1. PM: требования и архитектура.
2. UX/UI: сценарии, экраны, состояния и локализация.
3. Инфраструктура: Firebase, Google, Apple и конфигурация окружений.
4. iOS: AuthCoordinator и безопасный мост, восстановление сессии.
5. iOS: Google Sign-In.
6. iOS: Sign in with Apple и nonce.
7. Frontend: экран аккаунта и интеграция реальных состояний.
8. iOS: выход, повторная авторизация и удаление аккаунта.
9. QA: автоматизация и проверки на устройствах.
10. Release: privacy, документация, английские материалы и TestFlight.

Работа ведётся последовательно по этой очереди. Внешняя настройка может выполняться владельцем, пока завершается дизайн; задачи реализации не объявляются завершёнными без рабочего провайдера. Роли обозначают ответственность, а не назначение несуществующих участников.
