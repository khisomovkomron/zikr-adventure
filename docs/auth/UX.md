# 1.1.0 — UX/UI: начальное проектирование

Задача ZKR-14, статус In Review. Это описание интерфейса, а не реализованный вход.

## Размещение

Настройки → первая группа «Аккаунт». Экран счётчика и onboarding остаются доступны без входа. Визуальные токены существующего приложения сохраняются: спокойные карточки, текущая типографика, светлая/тёмная тема. OAuth-страницы не встраиваются в HTML.

## Режим без аккаунта

Заголовок: «Аккаунт».
Текст: «Войдите через Google или Apple. Можно продолжать пользоваться приложением без аккаунта».
Две равноценные кнопки официального вида: «Войти с Apple» и «Войти с Google».
Примечание: «Счёт и история хранятся только на этом устройстве. Вход пока не включает облачное сохранение».
Отдельная ссылка на актуальную политику конфиденциальности.

## Вход

После выбора провайдера: «Открываем вход через Apple/Google…», обе кнопки временно недоступны. Нативный flow принимает отмену. При отмене вернуться к guest без сообщения об ошибке. При ошибке сохранить карточку, показать «Не удалось войти. Попробуйте ещё раз»; для отсутствия сети — «Для входа нужен интернет. Счётчик доступен без сети». Ошибка объявляется VoiceOver один раз. Повторное нажатие не запускает второй flow.

## Вошедший пользователь

Показывать имя, если оно есть, иначе «Вы вошли в аккаунт». Ниже — используемый провайдер; email необязателен, relay-email Apple не считать ошибкой. Примечание о локальном счёте остаётся видимым.
Действия: «Выйти» и отдельное «Удалить аккаунт» в разделе управления. Нет редактирования профиля, объединения провайдеров или облачного значка синхронизации.

## Выход

Диалог: «Выйти из аккаунта?» → «Ваш счёт и история останутся на этом устройстве».
Кнопки: «Отмена», «Выйти». После успеха guest. При сбое сообщить ошибку, не показывать ложный выход.

## Удаление

Диалог: «Удалить аккаунт?» → «Учётная запись будет удалена. Счёт и история на этом устройстве сохранятся. Для их удаления используйте сброс прогресса в настройках».
Кнопки: «Отмена», «Удалить аккаунт». При необходимости — повторный нативный вход с пояснением причины. Во время операции действия отключены. Успех только после подтверждения сервера и необходимого отзыва Apple tokens. При ошибке аккаунт не считается удалённым; доступен повтор.

## Смена аккаунта

Выйти → войти другим способом. Напоминание: локальный прогресс относится к устройству и остаётся прежним. При конфликте Firebase подсказать первоначальный способ входа, не связывать UID автоматически по email.

## Доступность и локализация

Контролы не меньше 44 pt, видимые focus states, достаточный контраст; loading и error доступны VoiceOver. Тексты не обрезаются при масштабировании и на маленьком экране. Требуются русская, английская, узбекская, таджикская, казахская и кыргызская локализации. Подготовлены 22 строки для каждого из шести языков в design/strings.json. Переводы требуют языкового review; проверка VoiceOver на iPhone ещё не выполнена.

## Что осталось

Проверить предложенный дизайн и переводы. UI-код приложения выполняется отдельно в ZKR-19; официальные нативные компоненты Apple/Google и VoiceOver проверяются на устройстве в ZKR-21.

## Макеты и результаты проверки

Подготовлен preview.html: 9 состояний, 6 языков, тёмная/светлая тема и переключатель крупного текста. Это отдельный макет без настоящей авторизации и без доступа к данным приложения. Кнопки провайдеров схематические: финальная реализация использует официальные компоненты. Повторная авторизация выполняется исходным провайдером для текущего UID, а не любым произвольным аккаунтом.

- На ширине 320 px во всех 6 языках с крупным текстом проверены обе темы: нет горизонтального переполнения и обрезанных кнопок/карточек (12 комбинаций).
- Все кнопки не ниже 44 CSS px. Это проверка макета, не доказательство физических размеров на iPhone.
- Контраст проверенных текстовых пар: 4.87:1–14.06:1. Disabled-state не считается активным текстом.
- Есть focus-visible, role=status/alert и доступные имена. VoiceOver, Dynamic Type iOS, focus trapping реального диалога и provider flows ещё не проверены.
- Сохранён screenshot preview-ru.png. Снимок не подтверждает реальную авторизацию.
